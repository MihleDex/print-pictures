# Ask Where to Save a PDF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the chosen printer makes PDF files, Print asks where to save and writes the file there.

**Architecture:** `cups` marks printers whose CUPS device is `cups-pdf:`. For those, the window opens `gtk4::FileDialog`, builds the usual print PDF off the UI thread and copies it to the chosen place; nothing goes to CUPS.

**Tech Stack:** as before; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-25-save-pdf-design.md`

## Global Constraints

- Dialog title "Save As". Existing UI strings unchanged.
- Other printers and the `print` command behave exactly as before.
- Never modify the user's pictures. Building and writing stay off the UI thread.
- Every task ends with `cargo test` passing and `cargo clippy --all-targets -- -D warnings` clean.

## Review Focus

1. A chosen name that already exists, with or without `.pdf` → never replaced without a confirmation (Task 2).
2. A folder that cannot be written (read-only USB stick) → a message naming the file; the window stays open (Task 2).
3. The remembered folder has been deleted → suggest the pictures' folder (Task 1).
4. Picture names with non-ASCII, `%` or several dots → the suggested name keeps all but the last extension (Task 1).
5. A location with no local path (a network share not mounted as a folder) → "Choose a folder on this computer." (Task 2, Step 5 only; no test).

fn a_name_without_pdf_gets_it_and_never_replaces_silently() {
    let dir = tempfile::tempdir().unwrap();
    let at = |name: &str| dir.path().join(name);
    assert_eq!(pdf_target(&at("a.pdf")), (at("a.pdf"), false));
